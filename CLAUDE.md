# Claude Project Workflow

## Session Initialization

At the beginning of every **new Claude session**, always execute the following workflow before making any implementation changes.

### Step 1 — Understand the Architecture

First use the command:

```text
/understand-architecture
```

This command should be considered the primary source of truth for understanding the project.

Run it:

* at the beginning of every new Claude session
* whenever the current session lacks sufficient architectural context
* whenever major architectural changes have occurred
* before making significant implementation decisions

Do **not** begin implementing features until the project architecture has been understood.

---

## Default Command Behavior

If the user starts a message **without** any slash command (`/write-code`, `/code-review`, `/write-document`), automatically apply the `/write-code` standards by default.

This means every coding task in this project follows the full coding standards—readability, maintainability, DRY, Single Responsibility Principle, scalability, testing practices, and language-specific best practices—unless the user explicitly overrides with another command.

---

## Development Workflow

For every implementation request, execute the following workflow in order.

### Step 1 — Understand Architecture

If this is a new Claude session, or if architectural context is insufficient, execute:

```text
/understand-architecture
```

Only proceed once the project architecture is sufficiently understood.

---

### Step 2 — Implement the Requested Changes

Use:

```text
/write-code
```

Implement the requested feature, bug fix, refactor, or enhancement while following all project coding standards.

---

### Step 3 — Review the Implementation

After implementation is complete, execute:

```text
/code-review
```

Review the newly implemented changes to ensure:

* architecture consistency
* code quality
* maintainability
* scalability
* performance
* security
* adherence to project standards
* no unintended regressions

Address any issues identified before considering the task complete.

---

### Step 4 — Update the Architecture Knowledge

Once the implementation has been finalized and reviewed, execute:

```text
/create-architecture-graph
```

Update the architecture knowledge base so it reflects the latest implementation.

This should include any relevant changes to:

* architecture graph
* module relationships
* service interactions
* APIs
* database interactions
* event flows
* design decisions
* documentation generated by the architecture workflow

The architecture knowledge base should always remain synchronized with the current codebase.

---

## Available Commands

| Command                      | Purpose                                                                                                                                    |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `/understand-architecture`   | Load and understand the project architecture before development.                                                                           |
| `/write-code`                | Write or modify production-ready code following project coding standards.                                                                  |
| `/code-review`               | Review implemented code for architecture, quality, security, scalability, and maintainability.                                             |
| `/create-architecture-graph` | Update the architecture knowledge base to reflect the latest code changes.                                                                 |
| `/write-document`            | Produce User Flows, Technical Designs, Architecture Documents, ADRs, and other project documentation before implementation when requested. |

---

## Override Rule

If the user explicitly starts their message with one of the following commands:

* `/code-review`
* `/write-document`
* `/understand-architecture`
* `/create-architecture-graph`

follow that command instead of automatically applying `/write-code`.

Otherwise, default to the complete development workflow described above.
